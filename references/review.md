# 回顾（日 / 周 / 月）

理论：`时间管理.md` 的「回顾与 PDCA」分支；`核查清单`、`考虑对策或终止计划`、`考虑变更方法` 等子笔记。

## 日回顾（每天一篇）

落点：`7-规划回顾/73-回顾/721-日维度/review-YYYY-MM-DD-星期X.md`（星期的写法是 `星期一 … 星期日`）。

流程：

1. 先 `settle --dry-run` 把数字给用户看；
2. 用户确认后 `settle --date YYYY-MM-DD`（不加 `--dry-run`）写入；
3. 读回笔记，补正文里需要人写的部分。

注意 `--dry-run` 的口径：它**不读前一天账本**，`weekly_*` / `spent_*` / `unmet_*` 都从 0 起算，只能当参考；`earned_*` / `planned_total` / `denominator` / `rate` / `spendable` / `late_*` 与真实结算一致。真实写入后用 `balance` 读回准确余额。

**`settle` 默认拒绝覆盖已存在的日回顾**：打印 `已存在 <path>；如需覆盖请加 --force` 并退出 1，一个字都不写。这是为了保护正文里人写的总结/确认/谋划/身份反馈。确实要整篇重算时先读旧内容，再在确认卡里写明「将覆盖正文」，然后加 `--force`；同一天连跑两次 `--force` 结果字节一致（幂等）。

前一天没有日回顾时，真实结算会提示「前一天没有日回顾，周账从 0 起算」——先 `backfill` 补前一天，周账才准。**读前一天笔记失败**（后端/HTTP 故障）时 `settle` 直接退出 1 且不写入：故障不等于「没有」。

正文六块：

1. **总结**：完成情况、K\*I、专注质量（中断符号数 + U 事件数）、养成情况（抵触 / 担心 / 身份认同）。
2. **确认**：已计划未完成 → 滞后则加快节奏或调整计划。
3. **谋划**：明天三件事；头天晚上规划、上班路上微调、到公司增补。
4. **积分**：今日得分、分母、完成率、明日可花、日 / 周余额、消费明细（数字全部取自命令输出）。
5. **身份反馈**：一句「你今天是什么样的人」，为积分淡出做准备。
6. **一个实验**：只改一个变量，明天看数据。

更正：在正文追加「更正」小节，并同步修正 frontmatter；不要重写整篇、也不要留两份。下次 `audit` 会拿滴答重算对比。需要重跑当天的账本时用 `settle --date <当天> --force`（默认会被拒绝），跑完重新读回正文，把人写的部分补回去。

`late_pending: true` 表示有逾期任务的主观/客观原因没确认：下次对话问一次，确认后用 `settle --date <当天> --late-subjective ID1,ID2 --force` 重跑该日（折扣 0.5，突破类不打折）。重跑会整篇覆盖正文，先读旧内容。

## 周回顾（周日）

1. `report --from <周一> --to <周日>` 拿数据和 Markdown；
2. 写 `7-规划回顾/73-回顾/722-周维度/review-YYYY-Www.md`（ISO 周；写完要用户确认）。

内容：

- **四类对象**：过期未处理、项目、将来也许、日程表。
- **趋势**：完成率、番茄、积分、睡眠 / 戒断。
- **卡住的项目**：有没有下一步。
- **下周三个结果 + 一个实验**。
- **容量检查**：不要把空闲时间填满。

## 月回顾（月末）

1. `monthly --month YYYY-MM` 拿完成率与金额；
2. 写 `7-规划回顾/73-回顾/723-月维度/review-YYYY-MM.md`（首次月结时目录由 `init` 建）。

内容：

- 工作日完成率、双休完成率、平均完成率；
- 月底金额（完成率 < 门槛 → 0；封顶 10% 工资；当月触发惩罚再扣 2/3，只扣一次）；
- **规则审计**：分是否通胀、惩罚是否过重、哪些习惯该退役；
- **PDCA**：0–3 个改动（改目标 / 改阶段 / 改小任务）；
- 识别懈怠、瓶颈（换方法）、恶化（终止计划清单）。

`report` / `monthly` 只打印，不写文件；是否落盘由 Claude 按确认卡决定（设计稿 §7）。

## 自动化与补账

- 每日自动结算：Windows 任务计划程序在 23:55 调 `gtd.py settle --date <今天>`（需用户批准，属于系统改动）。无人值守时超时折扣先不打，记 `late_pending: true`。
  - 任务计划程序不会继承 Claude Code 的环境变量：要么在系统环境变量里配 `PERSONAL_GTD_VAULT_DIR` / FNS 两件套，要么在脚本里显式设置。
  - 当天已经手动结算过时，23:55 那次会因「已存在……请加 --force」退出 1——这是保护，不是故障；要让它无条件覆盖才加 `--force`（会冲掉人写的正文）。
- 漏结算：`backfill --from ... --to ...` 按日期升序补齐；每周/每月回顾前先补。
  - **默认只补缺失日期**：已存在的日回顾会打印「跳过」并保持原样，不会冲掉人写的正文。
  - 只有用户明确要求重算历史某几天时才加 `--force`；`--force` 会用重算结果整篇覆盖，包括正文。先读旧内容，并在确认卡里写明会覆盖哪几篇。
  - `--dry-run` 只预览数字（同样受上面的账本口径限制），不写文件。
  - 中途某天读前一天笔记失败时那一天会失败（退出 1、不写入），整天汇总里会算进「失败」。
- 对账：`audit --from ... --to ...`，不一致时以滴答重算为准并修正 frontmatter；`audit` 不会写文件。
  - 对账字段：`earned_total`、`denominator`、`rate`、`spendable` 与周账三项 `weekly_earned` / `weekly_spent` / `weekly_balance`（查余额异常）。
  - 结算时确认过主观超时的日子，**对账要带同一份** `audit --late-subjective ID1,ID2`，否则重算按「未确认」不打折，必然对不上。看到「该日有主观超时折扣；请用 --late-subjective 复核」就是这个原因，别急着改 frontmatter。
  - `721-日维度` 里老的自适应日总结没有 frontmatter，会被判为「不是账本笔记，已跳过」，不是账本错误。

## 语气

数据 + 好奇，不责备。结尾肯定具体行为，不空夸；每周期只改一个变量。
