# 收集（欲望：产生 → 筛选 → 询问确认 → 记录）

理论：`时间管理.md` 的「欲望」分支；`核查清单`、`任务规划`、`拒绝他人` 等子笔记。

## 1. 产生

从用户的自由表达、日记、聊天、临时笔记里抽出**可独立执行的欲望**，但**不立刻写**。

- v1 范围：只处理当前对话 + 用户明确指出的文件。设计稿预留的可选 `scan --days 7`（扫最近 7 天日记与 `1-收集箱`，带去重状态）**v1 未实现**，不要假装能扫。
- 收集时只是单纯收集，不夹带判断和动作。

### 五块关注点（漏了要补问）

1. **自我提升**：感受（身体、情绪、思维、性格）与提升（精力、能力、品质）。
2. **任务规划**：家庭事业 + 六层（当前行动、当前项目、关注点/责任、目标、愿景、目的与原则）。
3. **环境扫描**：家里、办公环境。
4. **人际需求**：利益往来、关系加深、矛盾处理。
5. **思考与材料整理**：每周专题 → 收集 → 思维导图/流程图整理。

## 2. 筛选（顺序固定，不跳）

1. **应不应该**：动机（内在/外在）、意义与影响（自己 → 精力能力品质；环境 → 家庭事业社会）。
2. **能不能够**：精力、能力、品质；资源工具；环境条件与他人态度。
3. **值不值得**：精要主义（精简事情/步骤/指标）+ 四象限（重要性 × 紧急性）。

输出是「建议 + 一行理由」，不替用户定价值。

## 3. 询问确认（每次记录前必做）

给一张紧凑确认卡，等用户回「过 / 改 / 拒」：

```
📋 标题：写周报 $4
📁 清单：执行计划 / 执行部分
⚡ 优先级：高（重要且紧急）
🏷️ 标签：下一步, 精力好
⏰ 截止：明天 18:00
🍅 预估：2 个番茄
💡 理由：与“稳定工作”直接相关；不做会影响本周交付
确认：过 / 改 / 拒
```

- 「改」→ 按用户修改重出一张卡再确认。
- 「拒」→ 不写，问一句是「拒绝做 · 自己」还是「拒绝做 · 他人」。

## 4. 记录（按决定分三层，不跳层）

| 决定 | 落点 |
| --- | --- |
| 立刻做（3–5 分钟） | 不入库，直接做 |
| 稍后做 · 时间紧迫或步骤复杂 | 滴答**收集箱**（裸标题，不判优先级） |
| 稍后做 · 已筛选 | 滴答任务：priority + 必填标签 + 情景标签 + 标题末尾 `$N` |
| 稍后做 · 已排期 | 滴答任务：dueDate + reminders + 预估番茄（写 `content`，如 `预计 3🍅`） |
| 拒绝做 · 自己 | 情绪管理流程（不写任务） |
| 拒绝做 · 他人 | 用 `拒绝他人` 子笔记里的话术 |

积分只在「已筛选/已排期」时预填（公式见 `scoring.md`），收集箱里的裸标题不带分。

## 写入约束（滴答 CLI 0.1.8）

`task create/update` 只有：title、content、desc、all-day、start-date、due-date、time-zone、reminders、repeat、priority、sort-order、items、tags。

- 没有 parent、estimated-pomo、comment、column。子任务用 `--items`；预估番茄写 `content`；分组用标签或标题前缀。
- `--due-date` 按 UTC 写，用户说的是 +0800，写入前减 8 小时。
- 每次写入前有确认卡；删除只按用户点名的任务做，先预览。
