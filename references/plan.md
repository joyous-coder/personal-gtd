# 计划（排程与项目分解）

理论：`时间管理.md` 的「计划」分支；`日程的安排`、`任务规划`、`任务划分`、`将目标划到更小维度`、`继续细化`、`最小目标`、`指定最高与最低目标`、`竞争比较→SWOT` 等子笔记。

## 日程安排五步

输出必须是一条带**时间、地点、路线、缓冲**的时间线，不是任务堆。

1. **巡检**：过期未处理、项目进度、将来也许、已有日程。
2. **估算**：先查同类任务历史中位数（参考类预测），再按番茄修正。>5–7 个番茄拆分，<1 个合并；不确定的任务前加 `?`。
3. **选择**：重要的打 `@`；能做的看情境、资源、精力。
4. **排序**：
   - 压力大的先做；
   - 四象限（重要 × 紧急）；
   - 精力节律（早/中/晚）；
   - 大节按场景、中节按时间、小节按动作；
   - **路线聚类，不走回头路**：同地点一次办完，地点间按路线排，同地点内按动作先后；
   - 地点之间留 **10–15 分钟**，任务之间留 **20% 缓冲**；
   - 并发（自进行事件、双手自由时）与批量（重复动作按环节）。
5. **指定触发 + 分配积分**：
   - 触发写成 if-then：「如果到公司坐下，就先写 30 分钟周报」；
   - 积分按 `scoring.md` 的公式预填到标题末尾 `$N`；预填后用户可改。

## 项目分解（WBS）

保留原有：SMART（避免假大空全）、WBS、K\*I、6W3H、资源 +50% 缓冲、微化（微步骤 / 最小目标 / 继续细化）。

补充项：

- **DoD（完成定义）**：每个阶段「什么算完成」。
- **依赖与关键路径**：哪些步骤卡住整体。
- **里程碑与检查点**：什么时候必须复盘。
- **风险与 B 方案**：预演失败——「4 周后失败了，最可能因为什么？」
- **粒度**：超过 5–7 个番茄拆；少于 1 个合；不确定加 `?`。
- **学习目标**：新技能类项目写「练几次 / 覆盖哪些点」，不只写结果指标。
- **防刷分**：积分按父任务价格给，子任务不翻倍（见 `scoring.md`）。

## 落滴答（CLI 0.1.8 实际能力）

| 需要表达 | 0.1.8 做法 | 不存在的命令 |
| --- | --- | --- |
| 子任务 | `--items`，或标题编号 `1.` / `1.1` | `--parent-id` |
| 预估番茄 | 写 `content`，如 `预计 3🍅` | `--estimated-pomo` |
| 干扰 / 超时原因 | 写 `content` 或 `desc` | `task comment` |
| 分组 / 分栏 | 标签或标题前缀 | `project column` |
| 标签 | 任务写入字段含 `tags`，任务上的标签直接给 | `tag list/create`（标签本身要在 App 里建） |
| 专注记录 | 只读 | `focus create` |

写日期时 `--due-date` 用 UTC，用户时间是 +0800，转换减 8 小时；`focus list --from/--to` 用 `+0800`。

## 计划里的积分预填

- 新建或排程时预填；**存量任务不改标题**（结算时有效分 = 标题 `$N`，没写就按优先级底分）。
- 标题末尾 `$N` 是最终分，覆盖公式；`$0` 表示明确不计分。
- 每次写任务前给确认卡（见 `capture.md`）。
